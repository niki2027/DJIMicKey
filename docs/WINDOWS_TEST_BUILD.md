# 相机接收器 Windows x64 测试版

本测试版包含第 2 阶段的设备识别修改：保留 `2CA3:4011`，增加 `2CA3:4015`，统一接收器探测与输入来源筛选，并显示实际设备 ID。输入去重、断连恢复等后续检查仍按开发计划进行。

Windows 工作流成功表示该提交完成了原有 `Test.cmd`、`Release.cmd` 和完整便携包检查。它不代表你的接收器、无线链路或 ChatGPT 语音已经通过硬件验证。`BUILD-INFO.txt` 记录源码提交、实际运行链接及 EXE/DLL 校验值。

## 下载与运行

1. 在仓库打开 **Actions → Windows camera receiver test package → 成功的运行记录 → Artifacts**，下载名称含 `camera-4015` 和提交标识的测试包。GitHub 可能要求登录后下载产物。
2. 解压下载的外层 ZIP；如果里面还有测试版 ZIP，继续解压。确认 `DJIMicKey.exe`、`DJIMicKey.Shell.dll` 与说明、LICENSE 在同一文件夹。
3. 完全退出旧版（包括托盘实例），从新文件夹运行 `DJIMicKey.exe`。首次测试先不开启开机启动。
4. 用 USB 数据线连接接收器，检查界面实际 ID 是否为 `2CA3:4015`；接收器已识别与音频未就绪应分别观察。
5. 先用实体键盘验证目标应用的语音快捷键，再在程序中设置相同组合；不预设 ChatGPT 默认快捷键，也不以 `Win+H` 听写代替 ChatGPT 语音。
6. 开始按键诊断后短按配对键三次，在本机查看识别、收到 Raw Input、解码和发送快捷键的结果；Windows 接受模拟按键不等于 ChatGPT 已响应。诊断记录仅留在本机，不要上传到公开仓库或构建产物。
7. 检查长按、连按、普通音量键、暂停、退出和拔插重连。现有音量抑制可能影响同桌面其他来源的音量加，需单独记录；暂停或完全退出后应恢复。

回退时完全退出测试版，重新运行原版文件夹中的完整程序。不要把单个 EXE 覆盖到另一版本 DLL 所在的文件夹。

## 工作流触发与结果

工作流监听 `codex/camera-receiver-4015` 分支推送，支持手动触发。首次使用 Fork 的 Actions 时，如 GitHub 提示启用，先启用；工作流尚未进入默认分支时，手动按钮可能不可用，向上述工作分支推送新提交即可触发。没有运行记录时不能使用“重新运行”入口。

工作流使用 Windows 2022、.NET Framework 编译器及 MinGW-w64 x64 GCC，复用现有构建脚本。测试失败会使工作流失败；失败运行不上传可运行测试包。交互桌面测试如果受 runner 限制，也应作为实际失败排查。

成功运行仅上传完整程序 ZIP，不上传个人资料、设备诊断或测试日志。便携包只包含配套 EXE、DLL、使用说明、许可证与最小构建信息。GitHub 自身仍会生成标准构建控制台记录。
